The Readiness Score — Your Release Confidence Number

Every test run produces a single, actionable number. No more "we think it's probably fine."

87
/ 100
0–49 — Not ready for release. Critical failures.
50–74 — Caution. Review failures before shipping.
75–89 — Good. Minor issues only. Proceed with sign-off.
90–100 — Ship with confidence. All critical flows pass.
Score is calculated from:
  • Overall test pass rate
  • Critical user flow coverage
  • Flakiness penalty (unstable tests)
  • Trend direction (improving or degrading?)
Set a release gate: Configure a minimum score (e.g. 80). Your CI/CD pipeline will automatically block deployment if the score falls below it — removing human judgment from go/no-go decisions.

Plain-English Glossary

No jargon required. Here's what the technical terms mean in plain business language.

Selector
The technical address of a button or field on a webpage. Like a GPS coordinate for a UI element.
Self-Healing
When a UI element moves, the AI finds it at its new location and updates the test automatically. No human needed.
Orchestrate
The one-click button that runs the entire pipeline: explore → map → generate → run → score.
CI/CD
The automated assembly line that builds and tests software every time a developer makes a change.
Flaky Test
A test that sometimes passes and sometimes fails for no obvious reason. AIQA tracks and penalises flakiness in the score.
Impact Filter
Only run the tests that are relevant to the code just changed. Makes CI 40%+ faster.
LLM
Large Language Model — the AI engine (Claude, GPT-4, Gemini) that generates tests and diagnoses failures.
Readiness Score
The 0–100 grade that summarises your software's quality at this moment. Think of it as a report card before release.
Playwright
The under-the-hood engine that controls a real browser. Think of it as a robot that physically drives the browser.
Xray
A Jira plugin for managing test results. AIQA automatically syncs pass/fail results to Xray test records.
YAML Test File
The simple recipe format AIQA uses to describe what to test. Auto-generated by the AI; humans rarely need to edit it.
RAG (Knowledge Layer)
Retrieval-Augmented Generation — the AI reads your Jira tickets and uses them as context when writing tests. Tests stay aligned with requirements.
